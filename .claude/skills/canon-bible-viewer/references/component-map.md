# CANON Bible Viewer — Component Map

Architecture reference for the live app at `canon/src/CanonShelf.jsx`.

---

## Data Flow

```
books-manifest.json
  └─ adaptManifestBook()
       └─ activeBooks[]          ← shelf rail + division tour entries
            └─ openBook(book)
                 └─ fetch(/data/[book.dataFile])
                      └─ bookDataCache[book.id]
                           └─ GenesisFullViewer
                                ├─ adaptCapitulos()       → chapters[]
                                ├─ adaptPersonajes()      → characters[]
                                ├─ adaptTheology()        → theology[]
                                ├─ adaptFuentes()         → sources[]
                                ├─ adaptVersiculosClave() → keyVerses[]
                                ├─ adaptAnclasConfesionales() → wcfAnchors[]
                                ├─ adaptTiposYSombras()   → tiposSombras[]
                                └─ adaptContextoHistorico() → histCtx{}

personas-display.json
  └─ personasDisplay{}           ← fetched once at startup, passed to adaptPersonajes()

canon-global.json
  └─ globalData{}                ← fetched once at startup, passed to GenesisFullViewer
```

## CanonShelf.jsx — Top-Level State

```js
const [view, setView]                   // { mode: "shelf" | "division" | "book", id: number|null }
const [bookDataCache, setBookDataCache] // { [bookId]: bookData } — fetched on demand
const [personasDisplay, setPersonasDisplay] // name-keyed display config map (from personas-display.json)
const [globalData, setGlobalData]       // { epocasRedentoras: {es,en,pt} } (from canon-global.json)
const [lang, setLang]                   // "es" | "en" | "pt"
```

`bookDataCache` is populated lazily: first time a book is opened, its JSON is fetched and stored. Subsequent opens use the cache.

## openBook() — Book Loading

```js
const openBook = (book) => {
  if (book.ready) {
    setView({ mode: "book", id: book.id });
    // Always resolve dataFile from activeBooks — callers (DivisionTour) may pass
    // partial book objects without dataFile
    const fullBook = activeBooks.find(b => b.id === book.id);
    const dataFile = fullBook?.dataFile;
    if (dataFile && !bookDataCache[book.id]) {
      fetch(`/data/${dataFile}`)
        .then(r => r.json())
        .then(data => setBookDataCache(prev => ({ ...prev, [book.id]: data })))
        .catch(() => {});
    }
  } else openDivision(book.div);
};
```

The `fullBook` lookup is critical — `DivisionTour` builds its `d.libros` as minimal objects `{es, en, razon, id, ready, div}` without `dataFile`. Without this lookup, Exodus and any future book would silently fail to load when clicked from the division tour.

## GenesisFullViewer — Props and Derived State

```js
function GenesisFullViewer({ onBack, bookData, globalData, personasDisplay = {}, lang = "es", divisionName })
```

All data derivation happens at the top of this function:

```js
const chapters    = bookData ? adaptCapitulos(bookData.resumenCapitulos, lang) : [];
const characters  = bookData ? adaptPersonajes(bookData.personajes, lang, personasDisplay) : [];
const theology    = bookData ? adaptTheology(bookData.teologiaSistematica, lang) : [];
const sources     = bookData ? adaptFuentes(bookData.fuentes, lang) : [];
const keyVerses   = bookData ? adaptVersiculosClave(bookData.versiculosClave, lang) : [];
const wcfAnchors  = bookData ? adaptAnclasConfesionales(bookData.anclasConfesionales, lang) : [];
const tiposSombras = bookData ? adaptTiposYSombras(bookData.historiaRedentora?.tiposYSombras, lang) : [];
const histCtx     = bookData ? adaptContextoHistorico(bookData.contextoHistorico, lang) : {};
const epochs      = globalData ? (globalData.epocasRedentoras[lang] || globalData.epocasRedentoras.es) : [];

// Dynamic chapter count — used by xOf() and timeline width
const totalChapters = bookData?.capitulosTotal || 50;

// Era bands: derived from chapter era values when present (e.g. Exodus "Ley"),
// falls back to hardcoded CHAPTER_ERAS for books without era annotations (Genesis)
const hasBookEras = chapters.some(c => c.era && c.era.trim());
const chapterEras = hasBookEras ? /* group by era from chapters */ : CHAPTER_ERAS;
```

## Adapter Functions — `canonToViewer.js`

| Function | Input | Output |
|---|---|---|
| `adaptManifestBook(libro)` | manifest book entry | shelf book object with `dataFile` |
| `adaptCapitulos(arr, lang)` | `resumenCapitulos[]` | `[{ch, color, title, desc, verse, era}]` |
| `adaptPersonajes(arr, lang, displayMap)` | `personajes[]` + display config | character node objects |
| `adaptTheology(arr, lang)` | `teologiaSistematica[]` | `[{categoria, resumen, pasajes}]` |
| `adaptFuentes(arr, lang)` | `fuentes[]` | source card objects with popup |
| `adaptVersiculosClave(arr, lang)` | `versiculosClave[]` | `[{ref, text, nota}]` |
| `adaptAnclasConfesionales(arr, lang)` | `anclasConfesionales[]` | `[{cap, titulo, resumen, doctrinas, genesis, url}]` |
| `adaptTiposYSombras(arr, lang)` | `tiposYSombras[]` | `string[]` (one per type/shadow) |
| `adaptContextoHistorico(ctx, lang)` | `contextoHistorico` | `{HIST_PERIODO, HIST_GEOGRAFIA, ...}` |

### ERA_COLORS

```js
const ERA_COLORS = {
  "Primordial":      "#6B7F5E",
  "Patriarcal":      "#7A6B4F",
  "Ley":             "#8B6914",
  "Éxodo":           "#8B6914",
  "Conquista":       "#5A7A5A",
  "Monarquía":       "#4A6B8A",
  "Exilio":          "#7A4A6B",
  "Intertestamental":"#8A8A8A",
  "Ministerio":      "#C9A84C",
  "Iglesia":         "#6B5B95",
  "Consumación":     "#8B0000",
};
```

`eraColor(era)` uses `String.includes()` against each key — so `"Era Ley"` would match `"Ley"`. An era value that matches no key returns `"#888"` (grey). Add missing eras to `ERA_COLORS`; do not add them anywhere else.

## personas-display.json — Shape

```json
{
  "Nombre en español": {
    "id":    "shortid",
    "color": "#XXXXXX",
    "init":  "XX",
    "xCh":   N,
    "side":  "above" | "below",
    "badge": { "es": "...", "en": "...", "pt": "..." }
  }
}
```

Key = `personajes[].nombre.es` (exact match, case-sensitive). If a character's name is not found, `adaptPersonajes()` uses a fallback: grey `#888`, `?` initials, `xCh: 1`.

## Timeline Geometry

```js
const TOTAL_W = 4200;   // px — fixed total inner width
const xOf = (ch) => ((ch - 0.5) / totalChapters) * TOTAL_W;
```

`totalChapters` comes from `bookData.capitulosTotal` (40 for Exodus, 50 for Genesis, etc.). Characters are positioned by their `xCh` value from `personas-display.json`, translated through `xOf()`. Era bands span `xOf(from)` to `xOf(to + 1)`.

## JSX Structure (top-level)

```
<div>                          // App root (LAPIS_DEEP bg)
  <div />                      // 3px ornamental top bar
  <header>                     // Book title, Hebrew, tagline, meta grid
  <div>                        // Era legend (colored dots + labels)
  <div>                        // Book info panel (tabs + tab content)
  <div>                        // Hint text
  <div>                        // Timeline (drag-scrollable)
    ↳ era bands (absolute positioned divs)
    ↳ spine line
    ↳ chapter dots (48px circles, clickable → BibleGateway)
    ↳ character nodes (72px circles with name labels + stems)
  {tooltip && ...}             // Chapter hover tooltip (fixed, pointer-events none)
  {charTooltip && ...}         // Character hover tooltip (brief)
  {activeChar && ...}          // Character click popup (overlay)
  {activeSource && ...}        // Source click popup (overlay)
</div>
```

**Critical:** all conditional popup blocks must be inside the root `<div>` — placing them after the closing `</div>` causes a parse error. Verify bracket balance before any edit to the bottom of the component.

## Language Switching

`lang` state is `"es" | "en" | "pt"`. It is passed down to `GenesisFullViewer` and to every `adapt*` call. All trilingual objects in the CANON JSON (`{es, en, pt}`) are resolved at the adapter layer — the component only receives resolved strings.

`UI[lang]` provides UI chrome labels (tab names, section headers, button text). Content (book prose, verse texts, character descriptions) always comes from the JSON adapters.

## BibleGateway URLs

Chapter circles link to:
```
https://www.biblegateway.com/passage/?search=[BookEnName]+[ch]&version=[BIBLE_VERSION[lang]]
```

`BIBLE_VERSION = { es: "NBLA", en: "ESV", pt: "NAA" }`. Book English name comes from `bookData.titulo.en`. Verse ref links throughout the app go through `verseUrl(ref)` which uses a 66-book abbreviation map (ES abbreviations → EN book names).
